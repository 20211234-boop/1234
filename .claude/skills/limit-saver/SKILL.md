# 한도 절약 모드

사용량 한도가 빠듯하다. 답의 정확도는 그대로 두고, 쓰는 토큰만 줄인다.
켜면 이 세션이 끝날 때까지 유지한다. "절약 모드 꺼" 또는 "normal mode"라고 하면 한 줄로 확인하고 끈다.

## 켤 때

한 줄로만 알린다: "한도 절약 모드 켰습니다."

## 답변 규칙 (출력 토큰)

1. 답부터 쓴다. 서론, 요약 반복, 맺음 인사를 쓰지 않는다.
2. 한 문장에 한 가지 내용만 담는다. 꾸미는 말은 뺀다.
3. 표·제목·굵은 글씨는 꼭 필요할 때만 쓴다.
4. 숫자, 금액, 날짜, 법 조항, 명령어, 파일 경로는 줄이지 않고 그대로 쓴다.
5. "아니다·없다·만·제외" 같은 부정·한정 표현은 절대 빼지 않는다.
6. 코드나 문서를 고쳤을 때는 바뀐 부분만 보여준다. 전체를 다시 출력하지 않는다.
7. 사용자의 언어(한국어)를 유지한다. 줄이는 것은 문체지 언어가 아니다.

## 작업 규칙 (입력 토큰)

1. 파일은 필요한 부분만 읽는다. 큰 파일은 검색으로 위치를 찾은 뒤 그 부분만 읽는다.
2. 같은 파일을 다시 읽지 않는다. 이미 읽은 내용을 쓴다.
3. 서브에이전트, 병렬 에이전트, `/67`처럼 여러 번 돌리는 작업은 하지 않는다. 꼭 필요하면 먼저 묻는다.
4. 웹 검색은 한 번에 필요한 것만 한다. 결과가 충분하면 더 찾지 않는다.
5. 긴 명령 출력은 마지막 몇 줄이나 필요한 줄만 본다.

## 대화가 길어졌을 때

대화가 길어져 같은 내용을 다시 설명하거나 앞의 결정을 놓치기 시작하면, 한 줄로 제안한다:
"대화가 길어졌습니다. `/handoff`로 정리하고 새 대화에서 이어가면 한도를 아낄 수 있습니다."
(클로드 코드라면 `/compact`도 함께 안내한다.)

## 규칙을 깨도 되는 경우

아래 경우에는 짧게 줄이지 말고 정확한 문장으로 쓴 뒤 다시 절약 모드로 돌아간다.

1. 보안·개인정보 경고
2. 되돌릴 수 없는 작업(삭제, 전송, 덮어쓰기) 전 확인
3. 순서가 중요한 단계 안내
4. 사용자가 이해하지 못해 같은 질문을 다시 할 때
5. 파일·문서·메일처럼 대화 밖에 남는 결과물 (결과물 자체는 평소 품질로 쓴다)

## 사용자에게 알려줄 습관 (처음 켤 때 한 번만, 3줄 이내)

- 주제가 바뀌면 새 대화로 시작하기
- 긴 자료는 통째로 붙이지 말고 필요한 부분만 붙이기
- 길어지면 `/handoff`로 정리하고 새 대화로 넘어가기
